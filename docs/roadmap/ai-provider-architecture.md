# Дорожная карта: вынос нейросетевого слоя в отдельные сервисы

Основана на ТЗ «Архитектура нейросетевого слоя экосистемы RockCast для глобального рынка» (черновик у владельца, прошёл два ревью Codex и ревью Gemini). Факты о коде сверены с репозиторием 2026-11-13; расхождения ссылок ТЗ с текущим кодом перечислены ниже. Этапы не начинать до утверждения ТЗ владельцем; каждый этап — отдельное небольшое изменение с собственным откатом.

## Цель

Убрать нейросети из процесса `rockserver`: эмбеддинги, распознавание речи и LLM становятся отдельными сервисами с версионируемым API в новом репозитории модулей. Сервер остаётся оркестратором: принимает аудио (WebSocket) или текст (HTTPS) от клиентов, вызывает сервисы, хранит и ранжирует. Моделей и прямых вызовов внешних провайдеров в `rockserver` не остаётся.

## Решения владельца (действуют во всех этапах)

1. Все нейросети — отдельные сервисы с API; в `rockserver` нет моделей и прямых вызовов провайдеров.
2. Версионирование: HTTP — версия в пути `/v{N}/…`; gRPC — версия в имени пакета `stt.v{K}`.
3. Провайдер определяется языком: для каждой пары язык × задача задан основной и запасной провайдер; запасной — только при отказе основного. На старте запасные не заданы (поле есть; отказ основного = отказ обеих).
4. Язык общения выбирает распознавание и провайдеров. Цепочка: настройка аккаунта → настройка приложения из запроса → английский. Язык общения — не фильтр станций.
5. Язык и страна станции извлекаются из текста запроса.
6. Векторы хранятся и ищутся в PostgreSQL/pgvector; сервис эмбеддингов только считает.
7. Свои модели — Docker-контейнеры; CPU/GPU — вопрос размещения.
8. API `rockserver` принимает три формы входа с меткой источника (кто и какой моделью получил результат): аудио; готовый текст; готовая команда/интент (строгая валидация как недоверенных данных). Готовый текст для поиска — транскрипт-эндпоинт; готовая команда управления — только канал управления устройством с авторизацией. Метка от клиента помечается «заявлено клиентом».
9. Стартовые языки ru и en; провайдеры текущие (SpeechKit v1, YandexGPT-lite).
10. Сортировка станций — только на сервере; клиентская пересортировка и клиентский порог RockCast убираются (RC2).
11. Языки — подключаемые модули: один файл `languages/<код>.yaml` (лексика, словарь команд, справочники провайдеров, метаданные), читается только при старте, строгая схема, ключи провайдеров только именами переменных окружения. Язык доступен, только когда модуль валиден у всех потребителей (пересечение списков).

## Сквозные обязательства каждого этапа

- При изменении публичного HTTP — обновить `api/openapi.yaml` и контрактные тесты.
- Обновить `docs/status.md` и `docs/tasks.md`; проверить `docs/service-diagrams.html`.
- Прогнать `cargo fmt --check`, `cargo clippy --all-targets --all-features -- -D warnings`, `cargo test`.
- Unit-тесты без сети и реальных LLM; сервисные клиенты тестируются на детерминированных фейках.
- Таймаут каждого вызова + сквозной дедлайн: `rockserver` передаёт остаток бюджета (gRPC deadline / заголовок `X-Request-Deadline`); сервис не начинает повтор запасному без достаточного остатка; отмена при обрыве клиента.
- Обратная совместимость публичного API и голосового протокола, кроме явно зафиксированных изменений; аутентификация rockserver ↔ сервисы; сквозной correlation ID; секреты не логируются.

## E1 — репозиторий модулей + сервис эмбеддингов

**Выполнено 2026-11-13** (репозиторий `rock-llm-service`; итог и замер памяти — в его `docs/tasks.md`).
Против исходного текста ниже изменилось по решению владельца 2026-11-13: **все сервисы говорят с
rockserver по gRPC** (пакет `embed.v1`: `rpc Info`, `rpc EmbedQuery`, `rpc EmbedStations`; схема —
`rock-llm-service/proto/embed/v1/embed.proto`, контракт — `rock-llm-service/docs/contract.md`,
gRPC-редакция). `/metrics` каждого сервиса остаётся HTTP (Prometheus), health — штатный `grpc.health.v1`.
Сверка с `onnx-v1` пройдена **побитово** (векторы, токены, текст станции на 20 станциях снимка и 20
запросах ru/en): `vector_version` остаётся `"onnx-v1"`, 16 825 готовых продакшн-векторов не
пересчитываются. Оба репозитория переведены на компилятор Rust 1.100.0 (`rust-toolchain.toml`, digest
builder-образа обновлён).

Шаги (исходный план):

1. Создать репозиторий модулей, структуру compose, CI.
2. Сервис эмбеддингов (HTTP+JSON): `GET /v{N}/info` → `{version, model, dim, image_digest}`; `POST /v{N}/embed/query`; `POST /v{N}/embed/stations`.
3. Модель, префиксы E5 и шаблон текста станции — внутри образа по digest; текст станции строит сервис, а не rockserver.
4. Правило версионирования: опубликованная `/v{N}` никогда не меняет поведение; новый образ = новая N; каждый ответ несёт `version`.
5. Unit-тесты без сети и внешних моделей (golden-векторы).
6. Развёртывание + healthcheck.

Негативные сценарии: ответ с чужой `version` отвергается клиентом (тест в E2).

Приёмка: контрактный тест; healthcheck; развёрнутый экземпляр.

Откат: сервис независим, `rockserver` ещё не клиент.

## E2 — rockserver: клиент эмбеддера, таблица, ANN-ветка

Обновление gRPC-редакции (2026-11-13): клиент — gRPC (`tonic`, схема `embed.v1` из
`rock-llm-service/proto/embed/v1/embed.proto`, копия по коммиту сервиса), адрес —
`ROCKSERVER_EMBEDDER_ADDR`; токен в метаданных `authorization`, ошибки различаются по `reason`
`google.rpc.ErrorInfo` (контракт, разделы 1 и 6 gRPC-редакции). Остальные шаги без изменений.

Шаги:

1. Реализация `EmbeddingProvider` поверх gRPC-клиента (адрес — конфигурация деплоя); детерминированный фейк для тестов; ответ с чужой `version` отвергается.
2. Константа `EMBEDDINGS_VERSION`; таблица `station_embeddings_v{N}`: `station_id` PK → `stations` ON DELETE CASCADE, `embedding vector(dim)`, `fields_hash`, `created_at`, HNSW-индекс.
3. Жизненный цикл: старт в режиме без векторов; фоновая задача (readiness от неё не зависит): `/info` с повторами → advisory lock на выделенном соединении (освобождается при обрыве) → `ensure_table` (создание, если нет) → проверка схемы (тип `vector(dim)`, индекс; несовпадение → режим без векторов) → дозаполнение пачками короткими транзакциями без HTTP внутри.
4. Запись вектора — только если `fields_hash` станции на момент записи совпадает с отправленным (гонка с импортом).
5. Импорт: поддерживает `stations.fields_hash` (тот же хеш отправляемых полей); таблицы векторов не трогает — убрать инвалидацию `station_embeddings` из импорта.
6. ANN-ветка: вектор используется только при `e.fields_hash = s.fields_hash`; ветка включается после `/info` и проверки схемы, без ожидания полного покрытия; новые/изменённые станции до заполнения находятся лексическим поиском. Дозаполнение — только при старте и вручную, без периодического опроса.
7. `backfill_embeddings --version N` — ручное заполнение новой версии до релиза; переключение версии: заполнить N+1 → релиз с новой константой → откат = релиз назад → удаление N вручную после срока наблюдения.
8. В тестах таблицу создаёт та же `ensure_table` в тестовом хелпере; PostgreSQL-тесты на `TEST_DATABASE_URL` не зависят от фоновой задачи.
9. Проверить `EXPLAIN` — ANN использует HNSW; снять метрики до/после; recall ANN против точного векторного поиска на снимке E0.

Негативные сценарии: `/info` недоступен → режим без векторов, лексический поиск работает; гонка с импортом (hash не совпал — не пишем); невалидная схема таблицы → режим без векторов; обрыв соединения с advisory lock.

Приёмка: аудиты 1, 6, 7, 8 (см. таблицу ниже); метрики до/после; тесты смены полей → пересчёт, гонки с импортом, переключения и отката версии.

Откат: релиз назад; ONNX ещё на месте (удаляется в E3).

Клиент: токен в `authorization`, `x-correlation-id`, grpc-timeout, один breaker на сервис (5→30 с, переиспользованный `CircuitBreaker` с политикой контракта), ошибки маппятся по reason `ErrorInfo` без разбора текста (§6 контракта: model_not_loaded/unauthorized и т. п. не открывают breaker), отказ = деградация в метаданный поиск. Ответ с чужой `version` отвергается (тест); пачки ≤64, порядок ответа сверяется по id (тест).
- Схема (миграция `0030`, только DDL): `stations.fields_hash` — SHA-256 канонической сериализации отправляемых полей `name`, `tags`, `language`, `country_code` (части `name`, десятичное число тегов, теги, language, country_code через NUL; NUL невозможен в `text` PostgreSQL, поэтому границы однозначны; формат закреплён юнит-тестом с независимо собранной строкой) и `station_embeddings_v1` (`station_id` PK → stations ON DELETE CASCADE, `embedding vector(384)`, `fields_hash`, `created_at`, HNSW cosine). Строки создают только lifecycle-задача или `backfill_embeddings --version N`; старые `station_embeddings` и индексы 0004/0005/0027/0028 не тронуты (удаление вручную после перехода).
- Жизненный цикл (`EmbedderLifecycle`, спавнится после старта; readiness не зависит): Info с backoff 1…30 с → advisory lock `pg_advisory_lock(hashtext(table))` на выделенном соединении (освобождается разрывом; вторая задача ждёт — тест) → `ensure_table` (CREATE IF NOT EXISTS + проверка типа `vector(384)`, PK, валидного HNSW; несовпадение → режим без векторов с ошибкой в лог — тест) → включение векторной ветки сразу, без полного покрытия → дозаполнение пачками ≤64 (RPC вне транзакций, короткие транзакции), запись строки только при совпавшем `fields_hash` (гонка с импортом — тест), ленивая простановка NULL-хешей легаси-строк. Импорт пишет `fields_hash` и больше не инвалидирует векторы (тест). Смена полей → пересчёт на следующем проходе (тест). `backfill_embeddings --version N` — ручное заполнение (без адреса эмбеддера — внятная ошибка; staging v{N+1} не трогает v{N} — тест, аудит 8).
- ANN-ветка: кандидаты из `station_embeddings_v1 e JOIN stations s ON s.id = e.station_id AND e.fields_hash = s.fields_hash` (+ retired/health/язык/страна/исключения/пагинация), отбор `ORDER BY distance ASC, e.station_id ASC LIMIT n` — находка E0 №1 закрыта. Скоринг/веса не менялись (E9).
- Честная фиксация плана: чистый kNN `ORDER BY embedding <=> q LIMIT n` идёт по `station_embeddings_v1_hnsw_cosine_idx` (EXPLAIN в выводе оценщика, ассерт), но в боевом поиске двухключевой tie-break лишает HNSW-путь упорядочивания, и на 16 825 станциях планировщик выбирает seq scan + top-N sort (скан векторов 6.5 мс, полный запрос 127 мс; оценка join по `fields_hash` тоже занижена до rows≈1). Качество не страдает: кандидаты боевой ветки совпадают с точным top-200 (branch recall 1.0000@10/@100 в обоих языках), т. е. на этом снимке отбор точный и детерминированный. Чистый HNSW kNN при дефолтном `ef_search=40` даёт 0.866/0.910 recall@10 и ~0.43@100 — возврат индексного пути в боевой запрос (повышение ef_search/iterative scan или изменение формы) оставлен E9, где EXPLAIN и recall при селективных фильтрах входят в приёмку.
- Метрики (снимок E0 `2026.08.2-mobile.1`, 16 825 станций, одноразовый pg18 + локальный контейнер `rock-embedder:local`, заполнение 16 825 векторов через gRPC за 233 с): en `top1=0.298 top3=0.426 top5=0.468 recall@5=0.406 recall@10=0.470 mrr=0.359 empty=0` (база: 0.277/0.404/0.447/0.385/0.449/0.342/0; все не хуже, большинство выше — детерминированный tie-break перестал терять дубликаты на границе), ru `0.205/0.256/0.308/0.269/0.359/0.250/0` — точное совпадение с базой; негативы en 18/20, ru 5/15 — как в базе; критерий регрессии (−0.02 recall/MRR, без новых пустых) выполнен и ассертится оценщиком. Идентичность двух путей: режимы локального ONNX и gRPC-эмбеддера заполняют одну и ту же v1-таблицу и прогоняются одним оценщиком (векторы побитово равны по E1).
- Прод-включение v1-пути — отдельный деплой-шаг (зафиксировано в `deploy/README.md`): сначала контейнер эмбеддера (rockmodules `compose.embedder.yaml`, pool 1), затем rockserver с `ROCKSERVER_EMBEDDER_ADDR`; в этой задаче не выполнялся. Compose-сервис `embedding_backfill` (старый onnx-путь) оставлен как есть до E3; стартовый гейт полноты старой таблицы из `main.rs` удалён (заменён lifecycle-режимом «старт без векторов»).
- Аудиты: №1 — детерминизм кандидатов + recall не хуже базы + EXPLAIN (HNSW в чистом kNN; боевой план зафиксирован выше); №6 — текст станции строит сервис (rockserver отправляет только `{id,name,tags,language,country_code}`), вектор запроса — по raw_query без префиксов; №7/№8 — тесты смены полей/гонки/отката версии. Открытые находки: №2 (порог релевантности, E9) и RC2-кейсы rank.rs не менялись.

## E7 — сервис распознавания (gRPC) и голосовой прокси

Шаги в репозитории модулей:

3. Запасной провайдер: аудио сессии хранится только если запасной задан (на старте запасных нет — механизм проверяется тестами на фейковом втором провайдере); лимит в пределах публичного лимита сессии + общий лимит памяти на все сессии. Шаги в rockserver:

## E9 — единое ранжирование и отбор кандидатов

Шаги:

```
    ├─> E7 (STT)
    └─> E8a/E8b (клиенты)     E10, RC1 — параллельно
```
