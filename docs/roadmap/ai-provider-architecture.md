## 0. Правила работы

1. Этап начинается, только когда закрыты его зависимости (раздел 9). Иначе — остановиться и сообщить лиду.
2. Решения владельца (раздел 1) не пересматриваются. Противоречие с ними — остановиться, описать варианты.
3. **Проверки `rockserver`** (каждая — в foreground, до завершения, строго последовательно):
   ```
   source ~/.cargo/env
   cargo fmt --check
   cargo clippy --all-targets --all-features -- -D warnings
   cargo test
   docker restart rockserver-test-pg && until docker exec rockserver-test-pg pg_isready -U rs_test -d rs_test; do sleep 1; done
   TEST_DATABASE_URL=postgres://rs_test:rs_test@127.0.0.1:55432/rs_test cargo test --test postgres_integration -- --ignored --test-threads=1
   ```
   **Базовая линия исключений** (замерена на старой базе `391c591`; на `master` `43eb468` её перепроверяет первый шаг
   E0a — если список изменился, исполнитель фиксирует новый список в отчёте E0a, и дальше действует он): в
   `postgres_integration` до начала работ падают ровно 5 тестов, не связанных с поиском:
   `postgres_account_cleanup_is_preview_first_and_cascade_safe`, `postgres_account_session_rotation_deletion_and_ownership`,
   `postgres_admin_bootstrap_is_atomic_and_idempotent`, `postgres_admin_identity_foundation_rejects_invalid_hash_state`,
   `postgres_device_control_manifest_is_owner_scoped_and_tombstoned`. Их не чинить. «Тесты зелёные» в этом ТЗ всегда
   означает: всё остальное проходит, новых падений нет. Каждый новый/изменённый SQL-запрос — с интеграционным тестом.
4. **Проверки `rock-llm-service`** — по его ТЗ (`services-tz.md`, раздел 0); этапы этого документа его не меняют.
5. **Проверки `rockmobile`/`rockcast`** — из их `AGENTS.md` / `docs/agents.md`; **веб-кабинета** (`rockserver/web`) —
   `pnpm typecheck`, `pnpm test`, `pnpm build` (`web/package.json`).
6. Каждый этап обновляет `docs/status.md` и `docs/tasks.md` затронутых репозиториев; изменение публичного HTTP —
   `api/openapi.yaml` и контрактные тесты; изменение архитектуры — проверка `docs/service-diagrams.html`.
7. **Порог качества** (единый для всех этапов, меняющих выдачу): ни одна метрика эталонного набора (Top-1, Top-3, Top-5,
   Recall@10, MRR, доля верно пустых) по каждому языку не падает более чем на 2 п.п. относительно базовой линии E0, и **все обязательные
   случаи** (раздел 6.9) проходят. Порог 2 п.п. проверяется и по общему среднему, и **отдельно по каждому классу
   случаев** (6.9), в котором не меньше 10 запросов; в меньших классах — только обязательные случаи. Иначе этап не
   принимается без решения владельца.
8. Не коммитить, не пушить, не деплоить без явной команды владельца. Ветка — `RagFix`.
9. Без сети в unit-тестах (фейки сервисов и провайдеров). Секреты не читать, не печатать, не логировать.
10. Номера миграций — следующий свободный на момент этапа; порядок этапов задан зависимостями.

## 1. Решения владельца

1. **Все нейросети — отдельные сервисы с API** в новом репозитории модулей: эмбеддинги, распознавание речи (STT),
   разбор запросов LLM. В `rockserver` нет моделей и прямых вызовов внешних провайдеров.
2. **Версионирование**: HTTP API — версия в пути `/v{N}/…` (как у OpenAI); gRPC — версия в имени пакета `stt.v{K}`.
3. **Провайдер определяется языком**: для каждого языка и задачи (STT, LLM) — основной и запасной провайдер; запасной —
   только при отказе основного. Справочник — файл провайдеров языка `rock-llm-service/providers/<код>.yaml`.
4. **Язык общения**: язык из аккаунта (пользователь вошёл и язык задан) → язык из настроек приложения, присланный с
   запросом → **английский**. Выбирает язык распознавания и провайдеров. **Не** фильтр станций.
5. **Язык и страна станции** («рок на немецком», «станции из Германии») извлекаются из текста запроса.
6. **Векторы хранятся и ищутся в PostgreSQL/pgvector**; сервис эмбеддингов только считает.
7. Свои модели — Docker-контейнеры. **Эта версия программы — только CPU, без разделения на тарифы.** Всё, что
   требует GPU (BGE-M3, переранжирование, собственные STT/LLM, тарифы CPU/GPU), — RFC на следующую версию
   (`docs/rfc/`).
   **Размещение (2026-11-11):** сервисы — контейнеры в том же Docker Compose на текущем сервере (2 ГиБ), деплой
   и откат — общей процедурой; память замеряется в E1 и E11, сервер увеличивается, только если замер покажет нехватку.
8. Клиенты шлют поток звука (WebSocket) или текст (HTTPS). **Перспектива — распознавание речи и команд на устройстве**:
   API принимает аудио, готовый текст, готовый интент поиска, готовую команду управления — с меткой источника; всё от
   клиента — недоверенные данные; метка источника от клиента помечается в метриках «заявлено клиентом».
9. **Старт**: языки **ru и en**; STT — Yandex SpeechKit v1, LLM — YandexGPT-lite (закреплённая версия); **запасных
   провайдеров нет** (поле есть).
10. **Сортировка станций — только на сервере.** Клиентская пересортировка и порог RockCast убираются.
11. **Языки — подключаемые модули**; добавили язык — он в интерфейсе. **Лингвистика — в `rockserver`, провайдеры — в
    сервисах** (2026-10-15): `rockserver/languages/<код>.yaml` (стоп-слова, формы, страны, словарь команд, 6.1) и
    `rock-llm-service/providers/<код>.yaml` (провайдеры STT/LLM; контракт, раздел 2). Общего файла нет.
12. **Векторы — как в `master` (SRCH-009, SRCH-010; решение владельца 2026-11-11).** Одна таблица `station_embeddings`
    с происхождением вектора (model, version, dimension) и SHA-256 исходного текста; дозаполнение — отдельной задачей
    деплоя после импорта и вручную, периодического нет; сервер не стартует без полного покрытия текущей версии; смена
    версии — в окне обслуживания с отчётом о качестве. Смена без остановки (таблица на версию, две версии
    одновременно) — RFC-0010. Отдельный сервис эмбеддингов остаётся (решение 1).
13. Эталонные запросы: **черновик готовит Gemini, проверяет Codex, утверждает владелец**.
14. **Стартовые значения утверждены владельцем (2026-10-12)**; меняются только его решением:
    - качество: регрессия ≤ 2 п.п. по каждой метрике и все обязательные случаи (раздел 0, п. 7); recall ANN ≥ 0,95;
    - скорость: p95 ≤ 1,2 с от `commit` до результата при 10 сессиях; сквозной бюджет — текстовый поиск 10 с (решение владельца
      2026-11-11, как hotfix `master`), распознавание 10 с от `Commit` (голос = 10 с + 5 с на поиск, раздел 5); вектор запроса — 300 мс;
    - отказы: breaker — 5 отказов подряд → 30 с паузы → пробный запрос; кэш LLM — 24 ч, до 10 000 записей;
    - лимиты: эмбеддер — текст 1–512 символов, пачка до 64 станций; 60 запросов в минуту на клиента;
    - таксономия и разбор: в LLM — корневые жанры и жанры с ≥ 20 станциями, не более 150 тегов (6.9); цитата — не длиннее 4 слов; окно
      отрицания — 2 слова перед цитатой;
    - прочее: выключатель `ROCKSERVER_VECTOR_SEARCH`; язык `en` обязателен; токен `ROCK_MODULES_TOKEN`;
      RC1 — подавление 40 дБ (неравномерность полосы ≤ 1 дБ), конец фразы после 1,2 с тишины, фразы короче 0,3 с
      отбрасываются.
15. **Прилагательное национальности («немецкий рок», «Spanish rock») — ограниченный мягкий буст после итоговой оценки (E9), не
    фильтр и не отдельная ветка поиска** (2026-10-13). Явные формы («на немецком», «из Германии») остаются жёсткими
    фильтрами (E0a); вето прилагательных для фильтров сохраняется. Значения прилагательного задаёт языковой модуль
    (`nationality_modifiers`, 6.1), не LLM. Отдельная ветка кандидатов — только если E0/E9 покажут нехватку recall.
    Не делать сейчас: разбор значения прилагательного через LLM, реестр регионов, обучаемое переранжирование.

## 5. Общие межсервисные правила

Правила — **контракт, раздел 1** (аутентификация `ROCK_MODULES_TOKEN`, `X-Correlation-Id`, `X-Request-Deadline`,
повторы, breaker, health, формат ошибок, приватность). Сторона `rockserver`:
- генерирует `X-Correlation-Id` и передаёт его во все вызовы;
- считает бюджет от получения запроса (решение 14): текстовый поиск — 10 с (как в `master`, `src/http/search.rs:29`); голос — 10 с на распознавание от
  `Commit` плюс 5 с на поиск (в `master` поиск голоса — 5 с, `src/http/endpoints.rs:78`; отдельный таймаут операции
  потока — 15 с, `src/http/voice/protocol.rs:31`); вектор запроса — 300 мс; передаёт остаток в
  `X-Request-Deadline` / deadline gRPC; для STT — `Commit.deadline_unix_ms`;
- держит breaker на каждый сервис и действует по таблице «ответ → действие» (контракт, раздел 6): отказ — только
  транспорт, таймаут и 5xx, кроме `503 providers_unavailable`; все 4xx и `503 providers_unavailable` — фолбэк без
  открытия breaker;
- повторяет вызов не более одного раза и только на `409 unknown_taxonomy_version`;
- отображает ошибки сервисов в публичный формат `{code, message, request_id, details}` (`AGENTS.md`) или в фолбэк;
  `message` сервиса клиенту не передаётся.

## 6. Целевая архитектура (детали)

### 6.1 Языковые модули (лингвистика)

Решение владельца 2026-10-15: лингвистика языка — в `rockserver`, провайдеры — в сервисах. Файл
`rockserver/languages/<код>.yaml` (рядом — `languages/schema.json`, JSON Schema draft 2020-12) входит в образ
`rockserver`; провайдерских полей в нём нет. Общие правила обоих файлов (код = имя файла, кавычки, без секретов, чтение
только при старте, невалидный файл выключает язык, невалидный `en` — `rockserver` не стартует, список языков) —
**контракт, раздел 2**.

```yaml
format_version: 1
code: "ru"
display_name: "Русский"
lexical:
  stop_words: ["включи", "вруби", "поставь"]
  negation_words: ["не", "без", "кроме"]
  explicit_language_forms: { "на немецком": "de", "по-немецки": "de", "немецкоязычный": "de" }
  country_names: { "германия": "DE", "германии": "DE", "германию": "DE" }
  nationality_modifiers:
    - forms: ["немецкий", "немецкая", "немецкое", "немецкие", "немецкого", "немецкую", "немецком", "german"]
      values:
        - { type: "language", code: "de", priority: "primary" }
        - { type: "country", code: "DE", priority: "alternative" }
    - forms: ["латинский", "латиноамериканский", "латино", "latin"]
      genre: "latin"
  language_names: { "de": ["немецк", "deutsch", "german"], "DE": ["германи", "deutschland", "germany"] }
commands:
  stop: ["стоп", "выключи"]
  resume: ["продолжи", "старт"]
  add_favorite: ["в избранное", "лайк"]
  next_station: ["следующая", "дальше"]
  previous_station: ["предыдущая", "назад"]
```

- Схема: `code` — 2–3 строчные латинские буквы, совпадает с именем файла; коды языков в `lexical` — 2–3 строчные
  латинские буквы; коды стран — ISO 3166-1 alpha-2 (заглавные); `lexical`, `commands`, `display_name` обязательны.
- Переходный период до E7: локаль распознавания для SpeechKit (`ru` → `ru-RU`, `en` → `en-US`) — таблица в коде рядом с
  `yandex_speechkit.rs`, удаляется вместе с ним в E7 (контракт, раздел 2).

Смысловые правила заполнения `lexical`:

- `nationality_modifiers` (решение 15): запись — формы слова; `values` — список значений (тип `language` | `country`,
  код, приоритет `primary` | `alternative`); или `genre` — тег таксономии, если выражение жанровое (тогда `values`
  нет). **Правила заполнения** (проверяются ревью модуля): (1) сначала — не жанр ли это: есть тег в `genre_hierarchy`
  или устойчивый жанр (latin, britpop, j-pop, k-pop, italo disco, celtic, afrobeat) → `genre`; (2) языка с таким
  названием нет → только `country` (австрийский, швейцарский, американский, канадский, бельгийский); (3) язык
  международный → только `language` (испанский, арабский, английский); (4) язык и страна соответствуют один к одному
  → оба значения, `language` — `primary`, `country` — `alternative` (немецкий, русский, польский). Схема модуля
  проверяет: коды валидны, у записи ровно одно из `values`/`genre`, формы не пересекаются между записями и с
  `explicit_language_forms`.
- `language_names` строится из **Unicode CLDR** (названия языков и территорий на языке модуля и на английском) +
  ручные основы для падежей; содержит основы, по которым привязывается цитата LLM к коду (6.6).
- Валидация файла — в `rockserver` при старте (невалидный файл выключает язык, невалидный `en` — `rockserver` не
  стартует).
- Список загруженных языков сервисов: STT — `Languages` (gRPC), LLM — `GET /v{L}/languages` (контракт, раздел 2). `rockserver` при старте
  опрашивает их (повторы с паузой); пока сервис не ответил, его вклад считается «неизвестен», и язык в публичный
  список не попадает (кроме `en`, проверенного локально). Публичный `GET /api/v1/languages` → `[{code, display_name}]` —
  пересечение языков, валидных в `rockserver` и подтверждённых сервисами, подключёнными к этому моменту (до E6/E7 —
  только `rockserver`).

### 6.2 Сервис эмбеддингов

API — **контракт, раздел 3**; реализация — ТЗ сервисов, 4.1. Для `rockserver`: префиксы модели и шаблон текста станции
он не знает и не строит — отправляет поля станции (`id, name, tags, language, country_code`) и `raw_query`; каждый ответ
проверяет (6.3). Стартовая версия `v1` — `multilingual-e5-small`, `dim = 384`, текст станции совпадает с нынешним
`searchable_text` (сопоставимость с базовой линией E0).

### 6.3 Векторы в `rockserver`

**Как в `master`** (SRCH-009, SRCH-010; `src/persistence/embedding_postgres.rs`, `src/search/embedding_release.rs`,
миграции `0027`, `0028`, `deploy/README.md`, раздел «Offline E5 version change»). Меняется только источник вектора:
вместо ONNX в процессе — HTTP-клиент к сервису эмбеддингов (контракт, раздел 3).

- Хост — `ROCKSERVER_EMBEDDER_URL`, путь `/v{N}`; N — конфигурация деплоя. Выключатель векторной ветки —
  `ROCKSERVER_VECTOR_SEARCH=on|off` (по умолчанию `on`).
- Хранение — таблица `station_embeddings` `master`: происхождение `model`, `version`, `dimension` и
  `source_text_sha256` (SHA-256 исходного `searchable_text`, без префикса модели).
- **Ожидаемое происхождение закреплено в конфигурации деплоя** вместе с N: `model`, `vector_version`, `dim`. По нему
  `rockserver` проверяет покрытие при старте и сверяет `/v{N}/info`. Для `v1` — `intfloat/multilingual-e5-small`,
  `onnx-v1`, 384; тогда 16 825 готовых векторов `master` переиспользуются (условие — приёмка E1 сервисов, ветка «совпало»).
- Дозаполнение — `backfill_embeddings` `master` с HTTP-провайдером: только активные станции без вектора этого
  происхождения или с другим хешем текста; курсор по `station_id`; запись с повторной проверкой хеша. Задача деплоя
  запускает импорт и дозаполнение последовательно до проверки готовности; импорт удаляет вектор только при изменении
  текста станции.
- Проверка старта — как в `master`: у каждой активной станции есть вектор текущего происхождения с актуальным хешем,
  HNSW-индекс совпадает с выражением ANN-запроса; иначе сервер не стартует. Для версии, отличной от `onnx-v1`, нужен
  JSON-отчёт о сравнении качества (`ROCKSERVER_E5_QUALITY_REVIEW_PATH`).
- Эмбеддер недоступен при старте или во время работы, или `/v{N}/info` не совпадает с конфигурацией → векторная ветка
  выключается, ошибка в логе, повтор с паузой; поиск работает без вектора (как при сбое вектора запроса в `master`).
  Проверка покрытия при старте идёт по конфигурации и от доступности эмбеддера не зависит.
- `ROCKSERVER_VECTOR_SEARCH=off`: проверка покрытия при старте не выполняется, векторная ветка не включается.
- ANN-ветка — запрос `master`: версию задаёт происхождение вектора запроса.
- Смена версии — окно обслуживания `master`: остановить `rockserver` и Caddy; **импорт каталога в окне запрещён**
  (изменение текста станции удаляет её векторы всех версий и ломает откат); развернуть эмбеддер N+1; дозаполнить
  `vector_version` N+1 рядом со старой; запустить `rockserver` с новым N и отчётом о качестве. Откат — прежние N, образ
  и строки старой версии (они не удаляются). Старые строки удаляются вручную после срока наблюдения.

### 6.4 Сервис STT — сторона `rockserver`

Протокол `stt.v{K}` и его поведение — **контракт, раздел 4**; буферы, failover и память сервиса — ТЗ сервисов, 4.2.
`rockserver`:
- держит публичный WebSocket (лимиты 2 MiB / 60 с / 32 KiB остаются у него) и проксирует в gRPC-стрим: `start` клиента
  → `Start` с языком общения (решение 4); ограниченная очередь аудио (backpressure — не читать WebSocket, пока очередь
  полна); обрыв клиента → `Cancel`; `commit` клиента → `Commit` с дедлайном распознавания; half-close после `commit` —
  дождаться финала;
- транслирует `Transcript` в текущие события `transcript` с `is_final`; публичный протокол не меняется;
- отображает `ErrorCode` в текущие публичные коды ошибок голоса;
- `recognizer_mode` в публичном протоколе принимает и игнорирует; в OpenAPI — deprecated с описанием: режим определяется
  провайдером языка.

### 6.5 Сервис LLM — сторона `rockserver`

API `/intent` и `/command` — **контракт, раздел 5**; промпт, схема провайдера, кэш, запасной — ТЗ сервисов, 4.3.
`rockserver`:
- вызывает `/intent` с `taxonomy_version` (6.9) без списка тегов; на `409 unknown_taxonomy_version` — один повтор с
  `taxonomy`, если дедлайн позволяет; `taxonomy_version_conflict` — ошибка конфигурации в лог (error), фолбэк;
- принимает язык и страну станции из ответа только по правилам 6.6; ответ для модификатора национальности не
  использует;
- вызывает `/command` в канале управления устройством; ответ проверяет публичным `VoiceCommand::validate`;
- при фолбэке (контракт, раздел 6) — детерминированный разбор модуля (поиск) и `DeterministicCommandInterpreter` со
  словарём `commands` (команды). Спасение `master` сохраняется: ответ `unknown` при слове из словаря `commands` в
  тексте → детерминированная команда (`command.rs:252-306`); в `master` это работает только для базовых слов, после E6 —
  для всего словаря модуля языка.

### 6.6 Разбор запроса в `rockserver`

1. Язык общения (решение 4) → модуль; язык вне списка → `en`.
2. Нормализация модулем → `raw_query`, `core_term_count` (единая точка `validate_intent`, E0a).
3. Параллельно: лексический разбор; `/intent`; `/embed/query` по `raw_query` (таймаут 300 мс).
4. Слияние: лексика приоритетна. Язык/страна станции от LLM (и из готового интента с устройства) принимаются, только
   если **все** условия истинны:
   - `kind` = `explicit_language` (страна — `country_name`);
   - код валиден (язык — 2–3 строчные латинские буквы; страна — код из `country_names` модуля);
   - `evidence` после нормализации (Unicode NFC, lowercase, схлопывание пробелов) — подстрока нормализованного запроса,
     не короче 2 символов, содержит букву, **не равна всему запросу** и не длиннее 4 слов;
   - `evidence` содержит основу из `language_names[code]` модуля (привязка кода к цитате, CLDR);
   - `evidence` не содержит **самостоятельного** прилагательного из `nationality_modifiers` (вето: прилагательное
     фильтром не становится). Слова, входящие в распознанную явную форму («на немецком», «in German») или название
     страны, самостоятельными не считаются;
   - перед `evidence` (до 2 слов) нет слова из `negation_words`;
   - неоднозначность проверяется **по исходному тексту**, независимо от ответа LLM: если в запросе по `country_names`
     модуля найдено больше одной страны (или по `explicit_language_forms` — больше одного языка), страна (язык) не
     ставится, даже если LLM вернула одну.
   **Отрицание действует на оба пути**: перед явной формой или названием страны (до 2 слов) стоит слово из
   `negation_words` → фильтр не ставится ни лексикой, ни из LLM (лексически — с этапа E0a).
   Обязательные негативные тесты: произвольное слово как цитата; неверный код при верной цитате; вся команда как цитата;
   многословная цитата с прилагательным; «не из Германии»; «из Германии или Австрии»; Unicode-формы (NFD/NFC).
5. **Модификатор национальности** (решение 15) определяется только лексически, по `forms` модуля в исходном тексте,
   **после** явных форм и названий стран: слова, уже занятые явной формой («немецком» в «на немецком») или названием
   страны, модификатор не создают. Найдено самостоятельное прилагательное без слова из `negation_words` в окне 2 слов
   перед ним → в интент записываются его `values`
   (запись с `genre` — тег, не модификатор). Ответ LLM для модификатора не используется. Модификатор не фильтрует;
   он используется в бусте 6.8.
6. Замена интента при пустом ответе LLM (`service.rs:250-276`, ветки `empty_intent`/`missing_terms`): принятые фильтры и модификатор сохраняются.
7. Сервис LLM недоступен/`503` → детерминированный разбор модуля.
8. **Команды** (канал управления устройством): `/command`; отказ → `DeterministicCommandInterpreter` со словарём
   `commands` модуля. `VoiceCommand::validate` становится публичной проверкой и применяется ко всем источникам
   (LLM, детерминированный, устройство).

### 6.7 Входы с устройства (задел, решение 8)

Все поля — недоверенные. Строгая схема `/api/v1/voice/command` (расширение текущего запроса):
- `transcript` (обязателен всегда, как сейчас) — исходный текст фразы; без него `evidence` не проверить.
- `source` (необязателен): `{provider ≤64 симв., model ≤64 симв., on_device: true}`.
- `intent` (необязателен): формат ответа `/intent` + `taxonomy_version`. Ограничения: `action ∈ {play, show}`;
  `terms` ≤ 32 по ≤ 64 символа; теги принимаются, только если `taxonomy_version` совпадает с текущей (иначе теги
  отбрасываются, остальное используется); язык/страна станции — по правилам 6.6 п. 4 против `transcript`.
- Поведение: `rockserver` всегда выполняет свой лексический разбор `transcript`; при наличии `intent` он занимает место
  ответа LLM (сервис LLM не вызывается); лексика по-прежнему приоритетна. Конфликт `intent` и лексики решается в пользу
  лексики.
- Готовая команда управления: только по каналу управления устройством с авторизацией устройства; поле `command`
  (`VoiceCommand`) + обязательный `transcript`; проверка публичным `validate` и теми же правами, что сейчас.
- Метрики таких входов — «заявлено клиентом».

### 6.8 Отбор и ранжирование

**Решение владельца (2026-11-11): отбор кандидатов и формула оценки — как в `master` (SRCH-003, SRCH-002, SRCH-005);
переход на RRF — RFC-0009.** Основание — замер SRCH-005 на 50 эталонных запросах: RRF (`k = 60`) снизил MRR кандидатов
0,930 → 0,897 и Recall@5 0,948 → 0,923.

- Отбор и оценка — `SEARCH_SQL` в `src/persistence/postgres.rs` (`master`): лексические кандидаты с проверкой
  пригодного потока и триграммным сходством до `LIMIT`, отдельная ANN-ветка E5; при совместимом векторе
  `score = 0,70 · min(1, max(0, metadata_score)) + 0,30 · semantic_score`, без вектора — `metadata_score` в прежней
  шкале; порог `MIN_RELEVANCE_SCORE = 0,35` (`src/search/domain.rs`); затем жанровый постфильтр. Этапы этого ТЗ формулу,
  веса и порог **не меняют**; изменение — только через RFC-0009 или новое решение владельца с замером на эталонах.
- После перехода векторов на сервис эмбеддингов (E2) ANN-ветка и формула прежние (6.3).
- Порог применяется к `score` **до** буста: буст меняет порядок прошедших, но не выводит в выдачу и не убирает из неё.
- **Буст модификатора национальности** (решение 15): `final = score · (1 − w + w · match)`. Множитель работает на обеих
  шкалах `score` (с вектором и без), при `w = 0` порядок не меняется; `final` отдаётся как `score`.
  - **Данные станции не преобразуются.** Сравнение кода языка (и в бусте, и в жёстком фильтре) идёт по **множеству
    эквивалентных кодов** одного языка из таблицы ISO 639 (639-1, 639-2/B, 639-2/T, 639-3; например для немецкого —
    `de`, `deu`, `ger`; для английского — `en`, `eng`; для испанского — `es`, `spa`). Таблица — из стандарта ISO 639
    (данные CLDR), в коде как справочник, не вычисляется. **Усечение кода до двух букв запрещено**: `ger` → `ge` — не
    язык (`GE` — код страны Грузии; грузинский язык — `ka`). Код, которого нет в таблице (`gsw`, `ken`, `zgh`, `fil`),
    совпадает только сам с собой.
  - `match` по одному значению: поле станции (`language` или `country_code`) совпадает с кодом → 1 для `primary`,
    0,75 для `alternative`; поле пустое → 0,5 (нейтрально: в снимке 4 362 из 16 825 станций без языка); поле
    заполнено другим кодом → 0.
  - `match` станции — **максимум** по всем значениям всех модификаторов запроса (не сумма): одно прилагательное не
    набирает несколько голосов.
  - Нет модификатора в запросе → `w = 0`, поведение не меняется. `w` подбирается в E9 по эталонам E0 (стартовое
    значение для подбора — 0,2; верхняя граница — 0,3).
  - Явный фильтр того же типа уже отсёк станции; буст по этому типу тогда ничего не меняет — отдельного правила нет.
- Нормировка `score` в [0,1] на всех путях и единая функция слияния для PostgreSQL и in-memory — RFC-0009.

### 6.9 Таксономия и эталонные запросы

- Таксономия — `genre_hierarchy`; `taxonomy_version = "sha256:" + SHA-256` канонического JSON (алгоритм — контракт 5.1) отсортированного набора

  - все случаи из тестов `rockcast/src/voice/rank.rs` (например «включи радио рок» → «Radio ROKS Classic Rock»);

### RC1 — RockCast: ресемплер и VAD
- `rockcast`. Зависимости: нет.
