# RFC-0006: история прослушиваний пользователя и архив эфира станций

- Статус: **Proposed** — версия программы не назначена (решение владельца); GPU **не требует**
- Дата: 2026-10-13, редакция 2 — 2026-10-14 (переписан от уже реализованного в `master` `cd1dbc9`)
- Автор: Claude (лид), по запросу владельца: «записывать, что конкретный пользователь слушает и что крутится на
  радиостанции»
- Связано: RFC-0005 (популярность); ТЗ `docs/roadmap/ai-provider-architecture.md` (6.8, 6.10);
  `docs/authenticated-radio-stream-relay-plan.md` (RR-001…RR-006)

## Что уже есть в `master`

**История пользователя — реализована** (PERSONAL-SYNC):
- таблица `history_records` (`migrations/0025_add_personal_data_sync.sql:20`): `user_id`, `station_id`, `started_at`,
  `last_played_at`, `ended_at`, `play_duration_ms`, ограниченный `metadata` (только для отображения), ревизии
  синхронизации и tombstones; удаляется каскадно вместе с аккаунтом;
- синхронизация между устройствами: `/api/v1/sync` (нативные клиенты) и `/api/v1/browser/sync` (веб-кабинет);
  разрешение конфликтов — «последняя запись побеждает»;
- лимиты: до 500 записей истории на пользователя, хранение 90 дней (`src/personal_data/domain.rs:14`, `:18`);
- синхронизируют все три клиента: RockCast, веб-кабинет и RockMobile (RM-12, `POST /api/v1/sync`).

**«Что играет» — реализовано как текущее значение, без архива:**
- **ретранслятор потоков** (RR-001/002): `GET /api/v1/stations/{id}/stream` — сервер сам открывает поток станции,
  читает ICY `StreamTitle` и держит последний `raw_title`; `GET …/now-playing` (снимок: `raw_title`, время,
  `missing`/`fresh`/`stale`) и `GET …/events` (SSE) — `src/http/relay.rs`, `src/http/endpoints/routes.rs:80`.
  Через ретранслятор уже играют веб-кабинет, RockMobile (`master` 2026-10-16) и RockCast для Cast (`master` 2026-10-16);
- устройства передают `playback.track_title` в состоянии плеера (канал управления, `src/device_control/state.rs:24`);
- **не хранится**: что звучало раньше — после смены трека прежний `raw_title` теряется.

**Чего нет:**
- архива эфира станций;
- связи истории пользователя с треками («что играло, пока я слушал»);
- управления согласием, выгрузки истории и операции «очистить всю историю»: история пишется у всех вошедших
  пользователей; отдельные записи удаляются через синхронизацию (`history.deletes`, `src/personal_data/in_memory.rs:84`),
  всё — вместе с аккаунтом; хранение — 90 дней.

## Предложение

### 1. Архив эфира станции (новое)

- Источник — **ICY-парсер ретранслятора на сервере**: смена `raw_title` станции → запись в архив. Данные получены
  сервером из потока станции, а не от клиента, — подтверждение числом сообщений не нужно.
- До RR-006 (один upstream на станцию) у станции может быть несколько параллельных соединений со сдвигом по времени:
  смена засчитывается, если такого `raw_title` у станции не было последние N минут (N — при принятии).
- `playback.track_title` от устройств, играющих мимо ретранслятора, — **не источник** архива (недоверенные данные);
  RR-003 выполнен (`master` 2026-10-16): все клиенты играют через ретранслятор.
- Таблица `station_plays(station_id, raw_title, artist, title, first_seen_at, last_seen_at)`: одна строка на
  непрерывное звучание трека. Разбор `raw_title` на «исполнитель — трек» — эвристика с вариантами разделителей; не
  разобралось — хранится только `raw_title`. Мусор (реклама, название станции, URL, пустые строки) отбрасывается по
  списку правил.
- Эфир известен только для станций, которые кто-то слушает через ретранслятор; отдельного опроса станций без
  слушателей нет (открытый вопрос 4).
- Это общие данные станции, без связи с пользователями. Срок хранения ограничен (открытый вопрос 3).

### 2. История пользователя: связь с треками и приватность (доработка существующего)

- Треки сессии не дублируются в `history_records`: «что играло, пока я слушал» получается соединением интервала
  записи (`started_at`…`ended_at`) с `station_plays` той же станции.
- Приватность: согласие на запись истории (настройка аккаунта), выгрузка истории, очистка всей истории одной
  операцией (удаление отдельных записей уже есть). Сейчас этого нет — открытый вопрос 2.
- Квалифицированные прослушивания для RFC-0005 выводятся из `history_records` (`play_duration_ms` ≥ 30 с) и из
  соединений ретранслятора — без новых событий от клиентов.

## Что это даёт

- Пользователю: «какая песня играла вчера на …» — по истории и архиву эфира.
- Поиску: «где сейчас играет Metallica» / «станция, где крутят Rammstein» — ветка кандидатов по архиву эфира за
  последние N дней (отдельное решение в рамках ТЗ 6.8).
- Каталогу: уточнение тегов станции по фактическим исполнителям в эфире.
- Позже — персональные рекомендации (отдельный RFC).

## Как решаем

Принимаем, если:
1. архив пишется только из ICY ретранслятора; дубли от параллельных соединений не возникают (тест на фейковом потоке);
2. на тестовом наборе реальных строк ICY разбор «исполнитель — трек» верен не менее чем в 90 % разобранных случаев,
   мусор отсеивается;
3. в логах нет `raw_title` рядом с идентификаторами пользователя (ТЗ 6.10);
4. если владелец требует согласие (вопрос 2): без согласия `history_records` не пишутся; выгрузка и очистка истории
   покрыты тестами.

## Риски

- ICY у многих станций отсутствует, нестандартен или содержит рекламу — архив будет неполным.
- Рост объёма архива — нужна чистка старых строк.
- Персональные данные: история уже хранится; для глобального рынка (GDPR и аналоги) согласие и выгрузка, скорее всего,
  обязательны — решение владельца.
- Архив зависел от перехода клиентов на ретранслятор (RR-003); переход выполнен в `master` 2026-10-16.

## Зависимости

RR-003 (клиенты через ретранслятор) — выполнен; RR-006 — для одного источника на станцию. После E10 ТЗ
(логи, лимиты). Поиск по эфиру — после E9.

## Открытые вопросы владельцу

1. В какую версию программы?
2. Нужны ли согласие на историю, выгрузка и очистка всей истории одной операцией (сейчас история пишется у всех
   вошедших, удалять можно по одной записи)?
3. Срок хранения архива эфира (история — уже 90 дней).
4. Нужен ли опрос эфира популярных станций, которые сейчас никто не слушает?
5. Поиск по эфиру — сразу или сначала только накопление архива?
