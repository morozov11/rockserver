# RFC-0010: смена версии эмбеддингов без остановки сервиса

- Статус: **Proposed** — версия программы не назначена; GPU **не требует**
- Дата: 2026-11-11
- Автор: Claude (лид). Решение владельца 2026-11-11: «сделать как в master, а наш вариант записать в RFC; отдельный
  сервис эмбеддингов при этом остаётся»
- Происхождение: ТЗ `docs/roadmap/ai-provider-architecture.md` редакций 1–5, раздел 6.3 (в плане — 2.2–2.3), этап E2,
  решение 12; контракт `rock-llm-service/docs/contract.md`, раздел 3 (до 2026-11-11)
- Связано: ТЗ 6.3, этапы E1, E2, E11; RFC-0001 (BGE-M3 как следующая версия)

## Контекст

Сейчас (ТЗ 6.3, как в `master` SRCH-009/010) векторы всех версий лежат в одной таблице `station_embeddings` с
происхождением (model, version, dimension) и хешем текста. Смена версии идёт в окне обслуживания: `rockserver`
остановлен, новая версия заполняется рядом со старой, сервер стартует, только когда покрытие полное и есть отчёт о
качестве. Развёрнута одна версия эмбеддера.

Цена: поиск недоступен на всё время дозаполнения. Для E5-small на 16 825 станциях это минуты; для более тяжёлой модели
(RFC-0001, BGE-M3 на CPU) — заметно дольше.

## Предложение

Прежний вариант ТЗ:

- **Таблица на версию** `station_embeddings_v{N}`: `station_id` (PK, `ON DELETE CASCADE` к `stations`),
  `embedding vector(dim)`, `fields_hash`, `created_at`; свой HNSW.
- `stations.fields_hash` — SHA-256 канонического JSON отправляемых полей; ANN берёт вектор, только если
  `e.fields_hash = s.fields_hash`.
- **Две версии эмбеддера одновременно**: контейнеры `embedder-vN` и `embedder-vN+1` за прокси по пути `/v{N}`.
- Сервер стартует **в режиме без векторов**; фоновая задача: `/info` → advisory lock на выделенном соединении →
  `ensure_table` (создать или проверить схему) → векторная ветка включается сразу → дозаполнение пачками по 64 с
  записью только при совпадении `fields_hash` (гонка с импортом).
- Смена версии: поднять N+1 → `backfill_embeddings --version N+1` при работающем N → релиз с новой константой
  `EMBEDDINGS_VERSION` → наблюдение → удалить таблицу и контейнер N. Откат — релиз назад.

## Что даёт и чего стоит

- Поиск доступен во время смены версии; откат — релиз назад без нового дозаполнения.
- Цена: второй контейнер эмбеддера в памяти на время смены (на VPS с 2 ГиБ это заметно); прокси по пути; DDL из
  `rockserver` во время работы; фоновая задача с блокировкой; режим «без векторов» после старта до проверки схемы;
  переделка хранения `master`.

## Как решаем

Принимать, только если окно обслуживания `master` стало реальной проблемой: замер времени дозаполнения новой версии
на полном каталоге превышает допустимый простой, который задаст владелец, или смена версий станет частой. Тогда — новый
этап ТЗ с переносом векторов `master` в схему таблиц по версиям.

## Зависимости

E1, E2 (сервис эмбеддингов и HTTP-провайдер в `rockserver`), замер дозаполнения по RFC-0001 или следующей модели.
