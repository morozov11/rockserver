# RFC-0007: модели решений (Clef, Jev) для команд и переранжирования

- Статус: **Proposed**. Путь A (облачный Clef) — возможен в текущей версии как ещё один провайдер; путь B (свой
  хостинг на V100) — следующая версия программы (требует GPU)
- Дата: 2026-10-13
- Автор: Claude (лид), по предложению владельца
- Связано: ТЗ `docs/roadmap/ai-provider-architecture.md` (6.5, 6.6, 6.8, решение 7); RFC-0002, RFC-0003, RFC-0004

## Контекст

Осенью 2026 вышел новый класс моделей — **модели решений**. Они не пишут текст: получают данные (`state`) и до 64
типизированных вопросов, отвечают вероятностями:
- `noul` — вероятность «да»;
- `choice` — один вариант из 2–255, с распределением вероятностей и уверенностью;
- `score` — положение на шкале из 2–10 уровней.

| | Jev (TypeSafe) | Clef / Clef-flash (Cloudflare) |
|---|---|---|
| Выход | 15.09.2026 | 01.10.2026 |
| Доступ | только облачный API; регистрация новых пользователей приостановлена с 22.09 | Workers AI; открытые веса, Apache 2.0 |
| Основа | закрытая | Qwen (Clef — 27B, Clef-flash — 9B) |
| Задержка (заявлено) | ~100 мс из США | flash 39 мс внутри Cloudflare, ~200 мс по сети из Европы; Clef 0,5–0,7 с |
| Цена | $0,042 / 1 млн входных токенов | $0,09 (flash), $0,24 (Clef) / 1 млн |

Формат запроса у обеих общий: переход между ними — смена адреса, ключа и имени модели.

Своя сборка: [`xormal/vllm-sm70`](https://github.com/xormal/vllm-sm70) — форк vLLM для V100 (sm_70). Он обслуживает
Qwen3.8-27B (генерация, OpenAI-совместимый API) и Clef (`POST /v1/systemone`) **на одних весах**: голова Clef и
low-rank поправки поверх общей модели, без загрузки второй модели. Веса —
[`alexxorm/Qwen3.8-27B-ABLITERATED-GPTQ-Int8-Clef`](https://huggingface.co/alexxorm/Qwen3.8-27B-ABLITERATED-GPTQ-Int8-Clef):
GPTQ-Int8, 33 ГБ, 2× V100 32 ГБ (tensor parallel 2), теги языков — en, ru, multilingual. По словам автора, решения
совпали с оригинальным Clef в 35 из 35 случаев (макс. разница вероятностей 0,0093); в продакшене с 12.10.2026.

## Где это подходит нам

| Задача | Подходит? | Почему |
|---|---|---|
| Голосовые команды (`/command`: play / stop / next / previous / volume) | **да, частично** | выбор действия — прямой `choice`. Но текст поискового запроса из «включи …» модель вернуть не может, а числа (громкость) — её известная слабость. Схема: действие — Clef, запрос и число — лексически или LLM |
| Переранжирование (альтернатива RFC-0002) | **да** | один вызов: `state` — запрос и до 64 кандидатов, по `score` на кандидата. Путь A не требует своего GPU |
| Тип упоминания языка/страны (`explicit_language` / прилагательное / страна) | возможно | `choice` по кандидату, найденному лексикой. Сейчас не нужно: решение 15 ТЗ — значения прилагательных только из модуля |
| Разбор поиска (`/intent`) | **нет** как замена | нужны термины и дословная цитата — модели решений текст не возвращают; тегов в наборе LLM до 150, вопросов — до 64 |

В пути B та же сборка даёт и генеративную модель (Qwen3.8-27B) — кандидат на замену YandexGPT для `/intent`
(RFC-0004) на том же железе.

## Предложение

**Путь A — облачный Clef (Workers AI).** Новый провайдер `cloudflare_clef` в сервисе LLM (`rock-llm-service`);
закреплённая модель (`clef` или `clef-flash`), ключ — переменная окружения. Два сценария с разной ценой:
- **Команды**: Clef — провайдер операции `/command` в разделе `llm` файла провайдеров языка (выбор действия; запрос и число
  громкости — лексически или генеративной LLM). Контракт `/command` (ТЗ 6.5) не меняется — **`rockserver` не меняется**.
- **Переранжирование**: новая операция `rerank` в сервисе и **новый вызов из `rockserver`** после итоговой оценки 6.8 — по схеме
  RFC-0002 (выключатель, фолбэк на порядок по оценке 6.8, бюджет из сквозного дедлайна). Это изменение `rockserver` и
  контракта сервиса; делается только вместе с принятием RFC-0002 или вместо его модели.

**Путь B — свой хостинг на V100** (следующая версия): контейнер на основе `vllm-sm70` как провайдер с тем же
API `/v1/systemone`. Переход A → B — смена адреса провайдера в файле провайдеров языка.

**Jev** — не берём, пока закрыта регистрация, нет своего хостинга и нет условий хранения данных для нашего тарифа.
Формат совместим — вернуться можно сменой провайдера.

## Как решаем

Для каждого языка (ru, en) и каждой задачи:
1. **Команды**: на наборе команд (из тестов `VoiceCommand` и эталонов) точность выбора действия не ниже YandexGPT;
   ни одной ошибки «стоп ↔ включи» на обязательных случаях; порог уверенности, ниже которого — фолбэк на
   `DeterministicCommandInterpreter`.
2. **Переранжирование**: критерии RFC-0002 (рост Top-1 или MRR ≥ 3 п.п., порог качества ТЗ по классам, обязательные
   случаи).
3. **Задержка**, замеренная **с нашего сервера**: p95 вызова ≤ 250 мс (переранжирование) и ≤ 300 мс (команды).
4. **Доступность**: стабильный доступ к Workers AI из региона нашего сервера (путь A).
5. Для пути B дополнительно: задержка на коротких запросах (у автора замеров нет — только длинные контексты),
   совпадение решений с облачным Clef на наших эталонах.

## Риски

- **Языки**: у Clef поддержка языков официально не заявлена (основа Qwen многоязычная); проверяется на эталонах ru.
- **Новизна**: модели вышли 2–4 недели назад; цифры качества и задержки — заявления производителей и обзоры.
- **Путь A**: зависимость от Cloudflare; доступность из региона сервера не проверена; запросы пользователей уходят
  внешнему провайдеру (как сейчас к Yandex) — нужна проверка условий хранения данных.
- **Путь B**:
  - основа — *abliterated*-вариант Qwen (намеренно снижен отказ от ответов). Для узкой классификации это не мешает,
    но в продуктовом генеративном использовании нежелательно; предпочтительна сборка на исходной Qwen3.8-27B
    (поправка между исходной и abliterated-базой в сборке есть — уточнить у автора);
  - int8 без калибровки, проверка соответствия — 35 записей на 10 примерах;
  - форк одного автора, только Volta, сборка из исходников с компиляцией ядер 15–30 мин; Docker не документирован;
  - V100 должны быть выделены под сервер целиком.
- Ещё один провайдер и тип вызова в эксплуатации.

## Когда

Путь A — после E6 (сервис LLM) и E9 (эталоны и ранжирование), отдельным решением владельца. Путь B — следующая
версия программы, вместе с RFC-0003/0004.

3. Начинать с команд, с переранжирования или с обоих?
